# Apple sign-in release setup

The iOS app uses native `expo-apple-authentication` and exchanges Apple's ID
token with Supabase. Google and guest access remain available. Android and web
keep their existing login options; this change does not add Apple web OAuth.

## Required configuration

1. In [Supabase Authentication → Providers](https://supabase.com/dashboard/project/htaktvkkxeylaelyvxoz/auth/providers),
   enable Apple and add `com.anonymous.slugswap` to **Client IDs**. Preserve any
   existing IDs. Keep nonce verification enabled. Native ID-token sign-in does
   not need a Services ID or a rotating OAuth client secret.
2. Enable **Sign in with Apple** for `com.anonymous.slugswap` in the
   [Apple Developer portal](https://developer.apple.com/account/resources/identifiers/list/bundleId).
   EAS can synchronize this capability during an authenticated build; ensure
   its provisioning profile includes it. The Expo config includes the plugin
   and `ios.usesAppleSignIn: true`.
3. Push the mobile changes to a branch to trigger the existing **Default**
   Xcode Cloud workflow. It archives the SlugSwap scheme for App Store Connect
   and already supplies the required public environment variables. Version
   2.0.2 / build 75 is configured; build 74 already exists in TestFlight.
   Xcode Cloud assigns its own sequential build number. The app-version runtime policy isolates 2.0.2 from
   older binaries that lack the native module. An OTA alone is insufficient.
   The workflow is pinned to Xcode 26.3 (17C529), the closest cloud version to
   the locally verified Xcode 26.2. Xcode 27 rejects deployment targets in
   existing third-party pods. CI installs Node 22 rather than unbounded latest.

If running locally with an existing ignored `ios/` directory, regenerate native
configuration with `npx expo prebuild --platform ios` from `apps/mobile` before
building. Do not use `--clean` on a native tree containing manual changes.

## Device validation before resubmitting

- On an iPhone and iPad, confirm Apple's native button appears beside Google.
- First login: choose Hide My Email; confirm a session and protected features
  work without asking for a replacement email. Repeat with Share My Email.
- Sign out and back in: Apple may omit the name; login must still work and
  must not erase an existing name.
- Cancel Apple's sheet: remain on sign-in without an error. Test offline/error
  handling and retry. Repeated taps must not open concurrent sign-in flows.
- Open a protected destination while signed out, then sign in with Apple and
  verify the destination is preserved. Check Google and guest access too.
- A private relay email can produce a separate account from an existing Google
  login. Do not assume account data merges across different email addresses.
- Refresh any App Store screenshots that depict the login screen. Select the
  tested new build in App Store Connect and resubmit it.

## Verification performed during implementation

Unit tests cover token/nonce forwarding, missing tokens, rejected sessions,
first-login names, repeat logins, private-email sessions, profile-save failures,
and cancellation. These tests do not substitute for Apple's real device flow.

All 34 mobile tests and the mobile TypeScript check passed. iOS and web exports
succeeded, and Expo config introspection produced the
`com.apple.developer.applesignin: ["Default"]` entitlement. Expo Doctor passed
19/20 checks; its remaining check reports seven existing SDK 55 patch-version
mismatches (Expo, dev client, maps, notifications, system UI, updates, and web
browser). The two new dependencies match the installed SDK.

Apple was enabled in the production Supabase project with client ID
`com.anonymous.slugswap`. The saved dashboard and public Auth settings both
confirmed Apple enabled; Google remains enabled. A successful real Apple login
was subsequently confirmed by the user in TestFlight build 77.

The Apple Developer App ID also has **Sign In with Apple** enabled as a primary
App ID. Provisioning profiles must be regenerated by the next archive. EAS was
cancelled in favor of the existing Xcode Cloud pipeline; no EAS build was queued.

A local native Release simulator build succeeded with Xcode 26.2. The login
screen was visually checked on iPhone and iPad using the installed iOS 26.2
runtime. Opaque JPEG captures are in
`apps/mobile/store-assets/app-store/apple-sign-in/`; both were uploaded to the
existing App Store screenshot collections. The unsigned simulator could not
complete Apple authorization; the user subsequently confirmed the TestFlight
build works on their device.

Xcode Cloud build 77 succeeded on Xcode 26.3, including App Store signing and
export. Version 2.0.2 (77) finished TestFlight processing and was assigned to the
existing internal `testers` group. Its What to Test field contains the Apple
login checks above. The App Store draft has version 2.0.2, build 77, updated
screenshots, and review notes. After the user confirmed the TestFlight build
works, version 2.0.2 (77) was resubmitted on September 18, 2026. App Store
Connect confirmed **Waiting for Review**.
